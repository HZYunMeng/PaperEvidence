# 工程原型验证记录

验证日期为 2026 年 10 月 8–9 日。当前是早期工程原型，已上传至 [GitHub](https://github.com/HZYunMeng/PaperEvidence)。下文按版本保留历史验收记录。

使用 Python 3.12、pdfplumber 0.11.9、Streamlit 1.65.0 和 reportlab 4.4.9，在本项目独立虚拟环境中运行。该环境复用了 Codex 提供的基础 Python 包；还没有在全新操作系统上完成安装验收。直接依赖版本已固定。

## 已验证

- 15 项自动化测试通过，包括真实 PDF 解析流程、表格、章节与页码边界、索引保存读取、PNG 来源高亮、没有检索结果的处理、伪造引用和数值拦截，以及 Streamlit 页面问答。
- 命令行导入与检索成功；示例 PDF 被解析为 2 页、8 个片段。
- 浏览器中实际完成测试 PDF 上传，页面显示 2 页、8 个片段。
- 浏览器中实际运行证据查询，展示表格与原文引用，PDF 第 2 页显示来源区域高亮。
- 依赖完整性检查通过。
- 7 个示例问题的检索对照运行成功，固定窗口和章节分块在 Evidence Recall@3 上均为 1.0。示例很小且是虚构数据，这不是质量提升的证据。

`demo/evidence-view.png` 是实际浏览器截图，`eval/smoke-results.json` 保存示例检索对照。GitHub Actions 配置已编写，还没有在远端运行。

## 第二轮：多语言检索与生成接口（工程版本 0.2.0）

- 31 项自动化测试通过。新增向量缓存复用与失效、长片段窗口来源映射、坏缓存拒绝、融合去重、API 请求范围、证据预算、截断回答、异常响应、token 用量及侧栏切换后清除旧结果的测试。
- 修复中文字符紧邻数值时的边界识别：`准确率99.2%` 会被完整识别，无法通过仅引用 `91.2%` 的校验。
- 在 CPU 上实际加载 multilingual-e5-small，模型提交为 `614241f622f53c4eeff9890bdc4f31cfecc418b3`。句向量依赖为 sentence-transformers 5.7.0、transformers 5.19.0、PyTorch 2.14.1。依赖完整性检查通过。
- 实际长文本检查生成 5 个窗口，加段落前缀后的输入最长 512 token，末尾 `91.2%` 保留在窗口中；实际检索仍返回原片段，超长问题被拒绝。脚本为 `eval/verify_local_embedding.py`，结果为 `eval/local-model-check.json`。代码也检查解码后重新分词的真实长度；这里仅验证窗口行为，不证明长论文检索质量。
- 命令行实际完成中文问题的融合检索与 JSON 导出，结果含来源页码、分数类型、模型版本与索引哈希。
- 浏览器实际选择多语言语义模式，用“提出的方法在测试集上准确率是多少？”查询英文示例，展示表格原文及 PDF 第 2 页来源区域高亮。截图为 `demo/semantic-evidence-view.png`。
- 云端生成进行了离线请求与响应测试，没有使用真实 API Key 发起生成；这些测试验证接口契约和拒绝行为，不证明供应商端到端可用或回答质量。
- 源码包解压至临时目录后，31 项测试再次通过；压缩包排除了虚拟环境、模型权重、论文缓存、用户数据和本地配置。此检查复用了已有解释器与依赖，不等同于全新环境安装验收。

同一份虚构 PDF、8 个片段、top-k=3，7 个事实各配英文和中文问题：

| 检索器 | 英文 Evidence Recall@3（7 题） | 中文 Evidence Recall@3（7 题） |
| --- | --- | --- |
| BM25 | 1.0 | 0.0 |
| E5 语义 | 1.0 | 1.0 |
| BM25 + E5 融合 | 1.0 | 1.0 |

另有 3 个无答案探针。语义和融合检索每题仍返回 3 个候选；BM25 也可能因术语重合返回片段。因此不能由这些分数推导拒答阈值。`eval/semantic-smoke-results.json` 保存逐题结果、模型版本、索引与数据哈希和耗时。

这是很小的虚构流程测试，没有保留测试集，也没有生成答案或人工支持率标注。上述数字不能用于真实科研质量的宣传。尚未在全新环境验收，也未在 GitHub 远端运行 CI。

## 第三轮：单元格引用与真实开发集（工程版本 0.3.0）

- 45 项自动化测试通过，包括 PDF 单元格坐标、源值读取、整表数值引用拒绝、模型覆盖标签或数值拒绝、合并单元格处理、旧索引兼容、指标防止错误页码或错误行列命中、离线云接口的结构化回答，以及页面行列选择。
- 浏览器实际从 Baseline 切换到 Proposed 行，选择 Accuracy 列，显示原文 `Proposed · Accuracy：91.2%`，并分别高亮行名、表头和数值区域。截图为 `demo/cell-citation-view.png`。
- JSON 来源索引升为版本 2，记录单元格结构；版本 1 仍可读取正文证据，需要重新导入才有单元格坐标。
- 对稀疏网格候选保留原可提取文本，减少图表误识别导致文字被遮掉；小字号正文使用 1 pt 间距保留单词空格。这些是启发式规则，不保证完整布局恢复。
- 实际下载并验证 3 篇 PMLR 论文哈希，完成 12 个事实的 24 道配对开发题和 3 个无答案探针。最终证据召回：BM25 15/24、语义 2/24、融合 8/24。六个目标表格事实均未获得可靠单元格结构。
- 已保留初始诊断与最终逐题结果，明确标注是开发集和 agent 制作的初稿，需要独立人工复核。没有生成答案质量指标。详见 [真实评测报告](REAL-EVAL.zh-CN.md)。

单元格绑定仅支持明确的简单结构；它不能判断选中的值是否回答了问题。未识别为表格的正文仍只有引文与数值出现校验，可能混淆方法或实验设置。

## 尚未验证

本地 Ollama 生成接口已实现，但当前机器没有安装 Ollama 或下载生成模型，所以未完成真实生成端到端验证。云端仍需供应商配置与真实密钥验收。扫描论文、视觉理解、公式结构恢复、真实论文答案准确率、保留测试集检索和神经重排均未验证，其中部分能力尚未实现。

引文和数值校验的测试不代表已解决幻觉。真实语义支持、表格行列归属、冲突证据与错误拒答需要独立评测。
