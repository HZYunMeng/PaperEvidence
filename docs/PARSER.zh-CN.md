# 几何解析器的接口与边界

v0.4.0 继续使用文本型 PDF 和固定版本的 pdfplumber，不增加 OCR 或布局模型权重。实现位于 `paper_evidence/layout.py`、`parsing.py` 和 `chunking.py`；文字坐标和规则的能力边界参见 [pdfplumber 官方说明](https://github.com/jsvine/pdfplumber#extracting-text)。

## 阅读顺序

先识别可接受的表格，再按字符中心从正文中排除对应区域，避免一条横跨两栏的文本行同时吞掉邻栏内容。对左右两侧都有足够文字的行，检测反复出现的中部空白。单侧短行不稀释检测比例；支持不足时保留原行提取顺序。

有可靠栏间空白时，将同一行两侧文字分开。宽标题和跨栏表格把页面分成阅读区域，各区域先读左栏，再读右栏。Block 的 `flow` 字段记录区域与列，分块遇到 flow 改变时停止合并。单栏保持自上而下顺序。

这只能处理常见双栏。三栏、侧注、异形绕图文字、跨栏段落与正文基线不齐仍可能恢复错误。检测到两栏也不证明整页阅读顺序正确。当前章节识别仍是常见标题规则，许多实际小节会落在 `Front matter`。

## 横线表格

候选需要至少三条端点对齐的横线、附近的 `Table N` 或 `表 N` 表注、含文字的单层表头和至少两行数字数据。表注是额外约束，不是可靠图表分类器。全无边框、无表注或复杂表头不自动推断；原有网格提取仍作为补充。

列边界来自数字数据行共同的水平空白。用整词中心分配列，不切割单词。表头可以比数据列更宽，但单元格坐标始终取实际字符外接框，不伪造物理网格。连字在 pdfplumber 的返回字符列表中可能重复，重建文本前按物理字符去重。

分组说明保留为跨列行，单元格坐标为 `None`，不能引用为数值。空白、合并、多行、无文字行名或无文字表头的选中单元格会拒绝绑定。重复行名在有可用文字上下文时附带来源列，例如 Architecture，引用和高亮一起保留上下文。

第一行作为表头、第一列作为行名仍是假设。规则接受一个表格不能证明它被正确解释；当前开发集的六个目标事实需要独立复核。多层表头、跨页表格、脚注与单位归属仍需人工查看原文或更强解析器。

## 长表格分块

结构化表格超过目标 1400 字符时，只在完整行之间拆分。各片段重复原表头和表注，并携带当前分组说明。单行超过预算时完整保留，不截掉尾部单元格。

每个片段的行号从自己的表头开始，生成模型和界面使用这个局部行号。表格来源框只包含该片段实际保留的行和表头，不能借完整表格的大区域为遗漏行提供证据。单元格与源 PDF 的坐标保持不变。没有结构化行的超长文本或表格仍可能超过字符目标。

## 数据兼容与缓存

JSON 索引仍使用 schema 2。TableData 新增可选 `caption`，旧索引默认空字符串；schema 1 仍能加载文字证据，不能补造单元格坐标。旧索引需要重新导入 PDF 才能获得新解析结果。

Streamlit 导入缓存和问答配置包含工程版本。升级后原问答结果清除；修改解析模块后应重启服务再验收，避免 Python 已加载模块或 Streamlit 缓存仍使用旧实现。

## 验证范围

单元测试用与论文标注无关的虚构内容覆盖列间不混读、长短栏、单栏保留、横线表格、拒绝多层表头、无表注回退、越界图形、重复行上下文、连字与长表格来源框。三篇真实论文的完整相关页与单元格高亮已目视核对。

真实结果与未解决的失败见 [开发集报告](REAL-EVAL.zh-CN.md)。这批论文已参与开发；需要新论文与独立标注者复核，才能判断通用能力。没有真实生成答案准确率、幻觉率或统计显著结论。
