# 证据清单：v0.6.0

2026 年 10 月 18 日。新增流程是把已经选定的源单元格加入清单，便于阅读者整理多个方法或论文的来源，再导出自己的记录。不调用生成模型或外部服务，不计算排名、提升幅度、实验条件一致性或语义支持。

## 操作

1. 通过标签查表、表格目录、逐页浏览或检索结果，选定可绑定的单元格并核对 PDF。
2. 点击“加入证据清单”。仅显示数值不会自动收藏；同一物理单元格再次出现时不会重复加入。
3. 展开页面上方“证据清单”，查看所选文件、方法、指标、原文值和 PDF 页码。
4. 选择已保存的记录，查看完整来源信息；原 PDF 完整 SHA256 与保存记录相同时，才能勾选显示其来源高亮。不同文件版本即使同名也不能混用。
5. 导出 JSON 或 Markdown，或移除一条记录。移除不影响原 PDF 和其他记录；当前 PDF 缺失或解析失败时，清单仍可导出。

清单只存于 Streamlit 当前会话内存，切换论文不清空，刷新、断连或重启可能丢失。导出需用户主动点击，当前不提供导入恢复、磁盘数据库或多人同步。导出的 JSON 是快照格式 schema 1，与检索索引 schema 3 分开。源码包不包含个人收藏记录。

## 保存内容与边界

每条记录从实际索引单元格重新读取，不接受用户或模型填写替代值。保留完整 PDF SHA256、去除目录后的文件名、可用标题、页码、行名、完整表头路径、选中值与来源框、同行原文和记录时的软件版本。物理身份使用完整文件哈希、PDF 页码、行名/叶子表头/值的字符框，不依赖可变化的分块 ID 或文件名。

缺少可绑定来源的单元格不能加入。跨层表头来自此前已有的引用适配器；新增清单不推断缺失的来源。保存快照不会随之后选择其他行、指标或文件而被改写。Markdown 导出对原表中的控制符和 HTML 做文本转义，JSON 保留原文。文件不含 PDF 内容、图片、密钥或用户文件的完整路径。

只有“加入”这一动作由用户决定；这不等于用户独立审查、论文数据真实或实验条件可比。导出表格按加入顺序排列，不代表排名。同值、同名方法和跨论文的指标都可能对应不同设置，需人工核查。

## 验证

107 项自动化测试通过，其中覆盖显式加入、去重、跨分块/重命名的同源单元格、文件版本区分、来源不符拒绝、快照隔离、多条记录删除与重新加入、真实切换另一份本地 PDF、缺失 PDF 仍可导出、只有哈希匹配才预览、逐页浏览收藏及 Markdown 转义。

页面交互使用 Streamlit AppTest；本轮没有真实浏览器截图或下载交互验收。检索和解析核心未改动，两组历史开发集的记录哈希仍保留，不把收藏功能当作检索或答案质量提升。本轮不启用生成模型，不新增质量指标。
